## Handoff and limits

Phase 0 establishes the host contract and a small transactional asset prototype. It does not implement Chimera's production snapshot, workers, patch assets, panel, or audio engine. Once those exist, Phase 7 must exercise real GUI Save/Save As and both Duplicate commands with the installed Rack application, plus patch reload on another machine or an isolated user directory. The headless fixture cannot prove those complete user flows. It also cannot prove that Rack cancels a failed save: the observed behavior is that Rack archives the module's safe fallback JSON. The module must show the failure and keep a coherent prior bundle. An orphan audio file can enter the archive after a manifest-stage failure; it is unreferenced and needs later worker-side pruning.

The unrelated Sibyl fixture failure remains a separate baseline issue. At the Phase 0 checkpoint, no Chimera audio engine, panel or production patch asset implementation existed; Phase 1 adds the isolated control/math core below.

## Phase 2 synthetic foundation complete

- Added `src/ChimeraReel.hpp`: an off-audio prepared active/reserve page pool; bounded eight-page capture/reclaim; write barrier and one-clone-per-page COW; fixed marker metadata; a published immutable cut; and safe recording stop on reserve exhaustion. The full-capacity synthetic test prepares 32,625 active and 32,625 reserve pages (133,632,000 raw audio bytes), rewrites every frame during capture, compares every frozen frame with the cut, and returns the full reserve after release. Partial last pages and repeated writes to a one-page region are covered.
- Added `src/ChimeraOwnership.hpp`: a non-spinning audio/maintenance token, counted snapshot readers, fixed 64-command and 128-completion SPSC rings (16 completion slots reserved), and service-owned store handles with a 256 MiB raw-payload ledger. A 100,000-command concurrent SPSC run preserved order; a stale host maintenance path completed two cuts without audio callbacks.
- Added `src/ChimeraJobs.hpp` and `src/ChimeraService.hpp/.cpp`: a bounded, lazily started plugin-scoped service with at most two workers, at most 16 unresolved jobs per generation, worker-side store preparation/retirement, and generation-based stale-result disposal. Jobs carry no `Module*` or widget pointer. `plugin.cpp::destroy()` drains the service off audio; merely opening Rack starts no Chimera worker or Reel. The registered module now exercises this service through token-specific polling and a bounded audio handoff.

Ownership flow for the current synthetic layer:

```text
UI/semantic callers --(non-RT dispatcher, later integration)--> service
service --(one producer, 64-entry SPSC)--> audio core
audio core --(one producer, 128-entry SPSC)--> service
worker prepares Reel --> service-owned StoreRegistry --> borrowed audio handle
audio cut/write barrier --> frozen page IDs --> counted worker readers
last reader finishes --> service queues release --> audio reclaims <=8 pages/tick
audio retires old handle --> service destroys store off audio --> ledger credit returns
```

The registered module's control dispatcher now polls only its generation token, admits a worker-prepared Reel to the ledger, sends a pointer-bearing POD command to audio, and waits for audio acknowledgment before detaching the old store for worker retirement. The old payload remains charged until retirement completes. On module removal, queued/completed jobs are discarded and an in-flight worker self-retires without accessing a Module or Widget. The module now creates neither a full Reel nor a worker when untouched. First audio connection or REC requests full-capacity worker preparation through the control dispatcher; an early REC is rejected visibly and must be pressed again after readiness. The core ownership token gates audio callbacks and stopped-host maintenance. Snapshot begin, ready, release and reclamation use bounded commands/completions; worker-facing readers see only frozen pages. The Rack-linked fixture proves an active overwrite leaves the frozen cut unchanged, a second reader delays release, and a stopped host can capture/reclaim and then make a newer cut without callbacks. This completes the Phase 2 synthetic foundation. Production SaveBundle fencing, encoding and durable patch assets remain Phase 7, so the fixture is not evidence of a saved recording.

## Phase 4 granular-playback checkpoint (gate open)

- Added `src/ChimeraGrains.hpp`, a Rack-independent four-slot engine for both finite Genes and full-Splice playback. Finite duration is latched in core frames; full-Splice musical voices expire by their own absolute effective-rate source travel. A separate non-reading primary cursor/cycle follows base rate only, preserving fractional full-Splice excess and resolving at most one boundary per frame. A fixed onset-phase accumulator implements Morph density, with two xorshift draws per onset and signed chord ratios latched in the engine. Each musical slot has one 48-frame outgoing cursor; repeated replacement uses a bounded scalar fade. The reader ceiling is eight. A 2,049-entry half-cosine table is built outside the audio callback and linearly interpolated in the callback. The finite density estimate is refreshed at most once per 32 core frames, while new voice duration is latched at onset.
