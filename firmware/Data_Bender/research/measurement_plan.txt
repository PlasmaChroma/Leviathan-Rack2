DATA BENDER: FOCUSED BEHAVIORAL MEASUREMENT PLAN
Purpose: close gaps left by static disassembly and manufacturer manuals. Proposed experiments, not measurements already performed.

COMMON SETUP
Record stereo audio plus event timing. Use a reference signal whose subsections can be uniquely recognized by correlation, rather than an ordinary musical loop. A deterministic pseudorandom sequence with distinguishable blocks works for playback-direction/rate/address reconstruction. A steady sine works for envelope measurements. Keep a precise list of knob/CV/settings and firmware SHA-256 for every run.
Run an executable harness faster than real time if the relevant functions can be isolated faithfully. Hardware captures remain necessary to confirm codec/analog amplitude response and event timing relative to actual buttons/gates. Do not label a replacement DSP model as an emulation of the original executable.

1. MACRO STOCHASTIC BEHAVIOR
Baseline: known buffer frozen; Corrupt disabled, windowing zero, width minimum; fixed clock. Test Bend alone first, Break alone next, then both. Keep stereo inputs identical so stereo event divergence is observable.
Sweep the manufacturer's pictured knob settings plus points immediately around binary-derived thresholds. Screen with 256 clock events at each candidate setting; collect 4096 events where probabilities or boundaries remain uncertain. At 8 Hz these are 32 seconds and 8.5 minutes respectively. Approximate 95% binomial margin near probability 0.5 is 6 percentage points for 256 events and 1.5 points for 4096 events; rare-event estimates need more observations.
For every event, log direction, speed target, measured speed trajectory, tape-stop duration, selected subsection, repeat count, silence fraction, and whether each value changed. Keep 'state still active' distinct from 'a new event was selected.'
Estimate conditional distributions versus knob position, transition matrix/autocorrelation, and event coincidence. Repeat at two buffer periods and three baseline repeat counts only after locating effects that depend on these variables. Compare Shared and Unique stereo by per-event L/R equality and temporal correlation.
Decisive outputs: per-zone event tables; normalized speed histogram; slew trajectories; repeat/index/mute distributions; constraints imposed by baseline Time/Repeats. These distinguish a seeded event scheduler from unrelated random LFO movement.

2. GLITCH WINDOW ENVELOPE
Baseline: Micro mode, rate 1, forward, no silence, no Corrupt, fully wet, frozen constant-amplitude sine. Choose an active period around 250 ms.
Test N=1,2,8 and window values 0,0.02,0.1,0.5,1.0, using exact internal values in a harness when possible. Estimate envelope after accounting for signal phase and capture latency. Fit candidates such as piecewise linear ramps and cosine/Tukey shapes; inspect residuals and boundaries rather than choosing a familiar window by appearance.
Determine whether default 2% denotes each flank or their combined duration; whether width is a proportion of each repeated subsection or the entire acquired buffer; whether a minimum sample/time floor exists; whether full scale forms a triangle, Hann-like lobe, or crossfade with another head.
Repeat key cases at speeds 0.5 and 2 to distinguish time-based envelope phase from read-position-based phase. Change Traverse mid-repeat and change Repeats near a boundary to discover where envelope phase resets. Repeat at a second sample rate only in a verified rate-configurable implementation; original hardware rate is fixed by firmware.
Decisive outputs: formula or table, phase variable, width normalization, default exact value, transition/restart rules, and any separate click-suppression fade unrelated to user windowing.

3. FREEZE / RESET / MIX TRANSITIONS
Feed continuously changing, uniquely marked blocks so new writes are distinguishable from retained playback. Hold Time fixed and trigger freeze/release at phase 0.1 and 0.9 of a clock cycle. Test latching and momentary button behavior separately from latching and momentary gate behavior.
Record the first/last captured source block, exact audible transition, continuing clock phase, and pending freeze-request state if instrumentable. Test two freeze requests before the next clock: does the second cancel, replace, or queue another action? Test button-plus-gate interaction with button state already enabled.
Repeat at Mix=0, a small positive value, 0.5, and 1.0. This locates the full-wet Freeze exception's actual threshold and reveals whether it changes stored Mix, effective Mix, or only routing. Change Mix after freezing and after unfreezing.
While frozen, expand Time and change Repeats/Traverse to verify old memory survives. Apply reset in internal and external clock modes, including immediately before/after incoming clock. Distinguish head-phase reset, acquisition-bank change, division counter reset, and destructive memory clearing.
Decisive outputs: state-transition table; scheduling edge for each control path; pending-event cancellation semantics; Mix exception threshold/lifetime; and reset/Freeze interaction. A single 'freeze boolean' is insufficient if transitions are queued by clock.
